# 首次测试示例：从自己的标准到报告

本示例供Windows开发者预览版首次操作。先完成 [运行手册](portal-runbook.md) 的环境、知识库、HTTPS及Workflow配置。它不是设备安全鉴定，也不提供可以直接导入的批准条款。源码中合成夹具只用于代码测试，不能作为国家标准入库。

## 准备标准PDF

准备一份合法取得、可在所选远程服务中处理的完整中国国家标准PDF；不要只取几页、截图拼接或解除受保护文件的限制。可在[国家标准全文公开系统](https://openstd.samr.gov.cn/bzgk/std/)核对标准号、版本和状态，再按该标准允许的方式获取文件。部分标准只提供题录或在线阅读，不意味着允许下载再分发；源码不会代为提供它们。

历史试点使用GB/T 8196-2018。若你有该版本的合法完整PDF，可用下述条款编号练习；若没有，可用自己获准使用、与当前六项防护方向相关的标准，按其实际结构重新复核和标注。无法取得可用PDF时，先完成README的“仅运行代码测试”路径，不必寻找历史 `data/` 文件。

在“标准资料库”上传文件。默认限制50MiB/300页、不接受加密或损坏文件；实际以页面限额为准。等待解析任务完成，再进入“对照复核”。**成功标志是完整页覆盖和可查看候选原文，批准数量仍为0**，不是看到条款就已入库。历史同一34页样本得到117候选，这个数量不是其他文件的通用判据。

## 一次条款复核示例

页面会自动预填可识别的信息并显示出处；状态、日期和核验来源仍由人工填写。可先按[辅助复核指南](assisted-review.md)集中查看异常与变更，普通条款批量对照，异常项单独处理。

以自己PDF中的GB/T 8196-2018 §5.3.7为例；本文不复制条款原文，也不替代复核：

| 页面字段/动作 | 怎么完成 |
|---|---|
| 标准信息 | 逐项填写标准号、完整名称、版本、适用范围；从原文核对，不填演示占位文字 |
| 状态、核验时间和来源 | 按本次实际查询结果填写；日期用YYYY-MM-DD或ISO日期时间，来源填可核查网址/出处，不照抄历史日期与状态 |
| 复核人 | 填写实际核对者，确保后续修改/批准有责任记录 |
| 条款号及层级 | 搜索5.3.7并对照PDF；只有你的文件层级确实时才使用 `5 / 5.3 / 5.3.7` |
| 原文与来源 | 核对标题、正文、数字、单位、否定词；勾选属于该条的真实来源块，检查跨页、脚注和图表。页码以自己的PDF为准 |
| 必要上下文 | 检查第1章范围、§5.3.1等前提是否为此条所需；用条款号/摘要选择。若还需父条款、其他前提或图表，一并处理，不能机械地照抄依赖清单 |
| 保存与批准 | 先保存修正，再逐项确认原文、边界、上下文、资产和范围，最后人工批准 |

首次可以围绕这一方向复核少量清晰条款及其必要上下文。相关上下文也必须批准，版本预览中的依赖集合才闭合。不要为凑“10条”批准无关条款；源码不携带原试点十条的人工批准记录。

**成功标志：** 已批准集合确实来自自己的PDF，边界、来源和依赖检查通过，待复核条款仍保持待复核。资产缺失、页覆盖不完整、边界未知、重复身份或未批准依赖，都应返回修正，不能跳过。

## 检索问题与知识库发布示例

在资料库勾选该标准，点击“预览并发布所选标准”。核对批准集合、仍待复核数量及同标准替换明细，随后核对自动问题草稿，必要时按下例改写，并逐题确认预期答案：

| 问题示例 | 如何设置预期 |
|---|---|
| 防护装置的外露边缘和尖角应如何处理？ | 如果你的批准语料确实覆盖此要求，设为可回答并勾选§5.3.7；依实际问题需要选择其他目标条款 |
| 设计防护装置时，如何避免防护装置本身产生新的危险？ | 只有批准语料确实覆盖时，设为可回答并选择相应条款，例如本版本的§5.3.1 |
| 这台设备主轴额定转速的具体数值是多少？ | 仅在本次批准语料确实不含答案时，勾选“无答案问题”，不选目标条款 |

这些问题是**标注方法示例**，不是随包交付的正确答案表。先根据自己的原文确定预期，再运行检索；不要见到结果后反向修改标注以凑通过率。无需手写UID；开发者详情中的JSON仅用于查看，历史UID不适用于你的文件。

填写复核人并提交索引、自检和发布。观察任务的导入、同步、映射、检索自检和发布阶段；技术错误会保留在诊断中。

**成功标志：** 发布任务成功、当前版本出现在页面、分块/元数据/映射全部回读一致，至少一道可回答题且Top-5命中率≥0.9、技术错误为0。无答案题仍返回相似候选可能发生，不能据此生成所问数值。这个门禁是检索排错指标，不是业务准确率。

## 报告成功判据与失败入口

提交后到“任务与报告”查看：

1. 任务状态为成功，包含本次Dify运行ID和报告ID。
2. 页面展示六项检查，报告状态为“待专业人员复核”；可下载Markdown/JSON。
3. 报告的图片关联、输入工况及知识版本属于本次提交。应用会校验HTTP/数据库回读一致，模型中间文本不会直接冒充报告。
4. “首次配置与诊断”再次检查后，真实链路项能够引用该配置成功报告的验证记录。

“证据不足”或“需现场确认”是允许的报告结果，不必为了得到风险结论而扩大语料或改写事实。只有连接诊断通过、HTTP200或Dify节点显示成功，都不足以证明本次完整报告成功；模型视觉和适用性判断仍要人工复核。

若失败，展开**当前任务**的“诊断与日志”，保留阶段、错误代码和运行ID，按 [运行手册](portal-runbook.md#诊断与排错) 排查。可下载脱敏诊断ZIP给协作者；不要发送配置密钥或原始业务附件。存在运行ID时恢复原任务对账，不能以连续重试新任务掩盖失败。
