# 自动整理、集中复核、确认发布

本轮在原门户上增加规则辅助复核，不新增LLM节点或远程模型调用。规则只生成建议和疑点，不改写原文，也不把机器输出标为批准。旧四个证据接口、七输入Workflow、人工批准/检索自检/报告回读门禁保持原有约束。

## 1. 上传与自动预填

上传完整PDF后照常由独立MinerU worker解析。封面/前部编号、中文标题块和第1章范围会形成标准号、版本、名称、范围建议；页面标明来源页及规则。独立编号标题会归入相应层级，图表中的行号不会直接拆成新条款。

标准状态、核验日期、核验来源仍为空，须人工核验后保存。相同标准/版本存在已批准文件时，建议沿用其编号写法，避免空格或横线差异造成不同条款身份；原文和状态不据此自动继承。既有解析资料打开时也能看到当前规则建议，无需为了获得建议重新跑OCR。

既有候选不被读取操作覆盖。若旧分片把独立编号标题合并在一段，单条复核区会展示结构建议及各段全文；填写发起人、核对建议后，可“按建议整理为待复核条款”。仅完整来源分区、没有人工原文/编号/备注/关联调整且尚未批准的段落可应用。已批准或已修订内容保留，受边界变化影响的依赖撤销批准；旧前缀仍不明确时继续保持待复核，不能因此直接发布。

## 2. 先处理文档级问题

“自动整理与集中复核”列出全文页覆盖、空页及归档问题。归档PDF不存在或哈希变化、实际缺页、缺失/未确认图表资产、来源缺失、重复身份和未明确条款号，会阻止批准或发布。

| 规则提示 | 人工核对重点 |
|---|---|
| 编号间断、逆序、父条款缺失、未识别格式 | 对照目录和正文，判断真实结构或OCR误读，不自动补号 |
| 跨页续文、括号不配对、块顺序异常 | 核对前页末句、后页首句、栏位和阅读顺序 |
| 图表/公式或未定位的图表引用 | 核对图表、脚注及其资产；区分本标准与外部引用 |
| 数字/单位/字符疑点 | 核对类似1O/10、分断小数、缺失区间端点、替换字符等；页面另列数字单位片段 |
| 建议上下文可能成环 | 逐项判断必要前提，不能把相互提及都当作依赖 |

规则并不能发现所有OCR漏字、漏否定词或单位错误。“无规则疑点”是工作分组，不是正确性证明；页面列出的数字片段也不等于全文已验证。空页可能是真空白，仍应查看原PDF；未知边界和缺失资产不能靠勾选强行通过。

## 3. 正常条款批量对照，异常逐项处理

先核对并保存预填的标准信息。没有保存时集中复核区默认折叠，方便先完成身份核验。

1. 展开集中复核，选“无规则疑点”，按条款号/原文搜索；每组8条。
2. 同屏对照当前原文与解析来源块或历史基准。通过每条“查看原始PDF第…页”链接核对真正的原页；来源块文字不能替代PDF视觉检查。
3. 勾选本组已核对条款（一次最多100条），核对父条款、范围、正文引用和原批准记录的上下文建议。可批量“采纳所选条款上下文建议”；不适用的建议在单条复核中自行选择并保存，不能机械接受全部关联。
4. 采纳建议后仍是待复核，选择与确认会清空，便于核对新关联。填写实际复核人，并确认所选全部条款的文本/数字单位、边界、上下文、资产及范围，再执行批量批准。
5. 切换“异常集中处理”，逐条打开原文和原页，修正或核对疑点；建议在复核备注记录结论。仍无法明确的内容保持待复核。异常条款不进入批量批准，单条审批继续受原来源和完整性门禁约束。

批量操作是一个事务：任一所选条款不满足条件，整批不会保存一部分批准。页面版本、基准或规则检查变化会使对照哈希失效，需要重新加载确认。审计记录保留批量动作、复核人及前后版本。批准后仍要等必要上下文全部批准并纳入版本，才能通过发布预检。

## 4. 相同文件复用，变化集中对照

同一测试台上传字节完全相同的PDF（即使改名），复用原文档、解析任务、人工批准与审计，不创建第二次解析。复用前校验本机归档仍与哈希一致；归档损坏时拒绝沿用，而不是静默覆盖。

内容不同的文件按新文件处理。系统在同标准/版本的已批准文件中选取对照基准，可从页面切换；没有其他文件时，可对照本文件的历史批准记录。默认集中显示新增、修改及受依赖传递影响的条款，另列删除项。未变条款可切换筛选集中查看，修改行用“- 基准 / + 当前”呈现，全文保留在两侧。

新PDF中的未变文字仍需确认新来源，不能自动继承旧PDF的批准。标准范围、状态等实质信息改变会影响所有条款；核验日期/来源变化单独列出，不冒充正文变化。保存元数据与编辑条款仍遵循原批准失效规则，建议关联也不会自动替你决定适用性。

基准文件可能只有部分条款获批，界面会区分“该条曾批准”和“该条未批准”。有结构建议时先核对分段，再进行上下文关联，避免用自动整理覆盖已形成的人工修订。

## 5. 问题草稿经确认后再自检

预览发布范围时，按已批准条款自动生成最多100道问题草稿，预选预期目标；只有标题的条款不凭空假设有答案。草稿取标题或正文片段作为线索，复核者应按真实查询改写并检查预期答案；这不是独立业务验收集。

- 每题可修改、删除、增补目标或改为无答案题。预选目标排在前面，可展开“核对预期目标条款全文”。
- 逐题勾选“我已核对本题与预期命中条款”。修改问题、答案性质或目标后，该题确认立即失效。
- 同一批准范围重复预览保留编辑和确认；范围变化须确认重新生成草稿。未提交的问题保留在当前页面，提交前避免刷新。
- 确认完毕后执行原有索引、自检与发布。后端核对草稿身份、批准范围和确认题目，保存人工确认来源、复核人和时间，再入队。至少一道可回答题，Top-5命中率≥0.9且技术错误为0的门禁不变。

开发者详情只读展示自检JSON，不需要手工复制UID。API仍支持人工标注cases；`draft_`前缀保留给机器草稿，必须携带草稿ID及逐题确认ID，缺少来源不能冒充人工标注直接发布。发布失败按原任务诊断恢复，不更改标注去迎合检索结果。

## 验证范围

合成资料用于自动测试和隔离的浏览器批量审批验证；真实两份已解析标准只做规则建议/界面读取和相同文件复用检查，没有新增真实批准、索引或模型调用。具体命令、结果和保留证据见 [验收记录](acceptance.md)。仍需专业人员判断标准状态、适用性和最终设备报告。
