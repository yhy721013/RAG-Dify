# 机械设备安全评估 RAG · Windows 开发者预览版

供开发者在本机测试和继续开发的源码原型：**PDF 标准 → 完整解析 → 人工复核 → 更新知识库 → 设备图片与工况 → Dify Workflow → 可追溯报告**。推荐使用本地门户，浏览器入口为 `http://127.0.0.1:8001`。

当前只支持**普通卧式金属车床的六项防护检查**：防护装置自身危险与锐边、连接牢固性、调整维护与人机交互、操作影响与耐久性、固定式防护装置安装、活动式防护装置关闭位置。报告始终待专业人员复核；技术流程通过不代表设备合规或安全。

> 源码包不含标准 PDF、设备照片、已批准条款、知识库、数据库或报告。历史验收中的“10 条知识库”属于开发时的独立试点，解压源码不会得到它。新实例必须自行准备资料、人工复核并发布第一个知识版本。

## 1. 开始前准备

| 准备项 | 仅运行代码测试 | 完整 PDF → 报告 |
|---|---|---|
| Windows x64、[PowerShell 7](https://learn.microsoft.com/zh-cn/powershell/scripting/install/installing-powershell-on-windows) | 必须；使用 `pwsh` | 必须；启动器按 Windows 验证 |
| [Python 3.12 与 Windows Launcher](https://docs.python.org/3.12/using/windows.html) | 必须；`py -3.12 --version` 应成功 | 同左 |
| 网络 | 首次下载锁定依赖需要 | 还需下载 MinerU 资源、访问 Dify/模型提供方及 HTTPS 隧道服务 |
| Git | 版本管理和导出源码包需要；解压 ZIP 运行不必 | 同左 |
| MinerU 4.0.2 独立环境 | 不需要 | 必须；预留模型/解析产物空间，硬件适配以本机实际解析为准 |
| Dify 工作区、专用空知识库、Workflow | 不需要 | 必须；需要创建单库权限 Knowledge API Key 和专用应用 API Key |
| Dify 模型提供方配置与可用额度 | 不需要 | 必须；默认适配 SiliconFlow 的 Qwen/Qwen3-Embedding-4B 与 Qwen/Qwen3.5-27B |
| 可达的 HTTPS 证据服务地址 | 不需要 | 必须；页面支持临时 Quick Tunnel，也可使用自己的 HTTPS |
| 合法取得的完整标准 PDF、同设备图片及人工复核者 | 不需要 | 必须；参考[首次测试示例](docs/first-test.md) |

不需要 Node 前端构建、Redis 或本机 Docker。云端模型可用性与费用由所选服务决定；模型出现在列表中不等于有调用权限，最终要用真实报告验证。

### 数据在哪里处理

| 阶段 | 数据去向 |
|---|---|
| PDF 上传、MinerU 解析、条款复核 | 本机 `data/portal`；门户固定调用本地 `mineru-kit`，不启用远程解析参数 |
| 发布知识版本、检索自检 | 批准条款的检索文本与标识发送到自己的 Dify 知识库，由其配置的嵌入模型处理 |
| 图片评估 | 图片、设备说明、工况发往 Dify；工作流把这些材料及检索证据交给配置的视觉/评估模型 |
| 证据准备、报告保存 | Dify 经 HTTPS 调用本机 8002 证据服务，报告在本机保存并回读；使用 Quick Tunnel 时流量经过 Cloudflare |

上传/复核页面 **8001 只供本机访问**。密钥由后端保存到 `.env.portal`，证据密钥还需绑定 Dify Secret；页面不回显已存密钥。请只上传允许交给这些远程服务处理的材料。

## 2. 选择一条开始路径

将源码解压到可写目录，在**含本 README 的项目根目录**打开 PowerShell 7。先确认 `pwsh --version` 和 `py -3.12 --version` 可用。

### A. 仅运行代码测试

```powershell
pwsh -File deploy/init-portal.ps1
.\.venv\Scripts\python.exe -X utf8 -m pytest -q
```

初始化会安装 `uv.lock` 中的轻量依赖，生成本机空配置和数据目录，不启动服务、不安装 MinerU、不访问真实 Dify。测试使用合成数据或脱敏夹具，无需填写云端密钥。预期：pytest 通过；测试数量及本轮实际结果见[验收记录](docs/acceptance.md)。

### B. 运行完整 PDF → 报告

```powershell
pwsh -File deploy/init-portal.ps1 -InstallMinerU
pwsh -File deploy/start-portal.ps1
```

首次安装可能需要较长时间。预期：终端提示页面、证据服务和 worker 已启动；打开 [本机门户](http://127.0.0.1:8001/)。**本轮启动一次即可**，后续配置在页面应用，不要再次执行启动命令。若从路径 A 转来，补执行带 `-InstallMinerU` 的初始化即可；已有配置不会被覆盖。

安装/启动失败时，终端会给出原因和 `data/portal-runtime/startup-bootstrap.html` 路径；Python 已运行的详细诊断另见同目录 `startup-diagnostics.html`。完整线性步骤见[门户运行手册](docs/portal-runbook.md)。

## 3. 完成页面五步配置

所有配置遵循“填写 → 保存草稿 → 空闲时应用 → 检查已应用配置”。空密码框保留原值。配置文件被外部修改或有活动任务时会阻止应用。

| 页面步骤 | 需要完成什么 | 成功标志 |
|---|---|---|
| 1 本机环境 | 核对 MinerU 路径、文件限额；必要时查看服务日志 | 诊断中的解析器、数据库和 worker 通过 |
| 2 专用知识库 | 在自己的 Dify 创建空库和仅限该库的密钥；填 ID/网址和模型；应用后初始化空库 | 初始化任务成功；知识库鉴权、模型与元数据检查通过 |
| 3 HTTPS 入口 | 安装向导链接的指定 cloudflared，启动本实例隧道并应用新地址；或填自有 HTTPS | 本机及 HTTPS 鉴权通过；空库的健康检查 503 不算网络故障 |
| 4 Dify 工作流 | **从页面下载当前环境的无密钥门户 DSL**，导入专用 Workflow；绑定 Secret、发布 API、停用公开 Web App；填写应用 API Key | Workflow 鉴权和已发布输入契约通过；人工确认项已逐项核对 |
| 5 检查与首测 | 检查已应用配置，再按页面指引上传 PDF、复核发布、上传图片 | 首份真实报告成功保存并回读；此时才验证完整模型和回调链路 |

仓库的门户模板用于开发阅读，首次导入以页面生成的 DSL 为准。只读诊断不调用模型，也不能替代 Dify Secret/模型绑定的人工确认。云端首次发布顺序、密钥获取及具体失败入口见[运行手册](docs/portal-runbook.md)。

## 4. 批量上传、集中复核与首份报告

资料库支持一次多选或拖入多个PDF，按文件显示上传/解析状态与原因。一个文件失败不阻止其余处理，可只重试该文件；重复内容复用原记录。每份文件限额不变，后台仍逐个解析；详见[批量上传说明](docs/portal-runbook.md#批量上传与单文件重试)。

本版会预填可从PDF识别的标准信息，集中提示缺页、编号、跨页、图表与数字单位疑点；无规则疑点条款可批量对照确认，异常逐项处理。相同文件沿用原记录，变化文件集中显示差异及受影响依赖。发布预览自动生成检索问题草稿，须逐题核对预期答案后确认。操作与限制见[辅助复核指南](docs/assisted-review.md)。

1. 合法准备一份完整国家标准 PDF；先用少量清晰、依赖可核对的条款走通流程。
2. 上传后等待完整解析，对照原 PDF 填写标准身份、范围和状态来源，核对原文、来源及必要上下文，按普通/异常分组人工批准。
3. 预览批准集合，核对自动问题草稿及预期条款并逐题确认，执行索引、自检和发布。未批准条款不入库。
4. 选择 1～4 张同设备 JPEG/PNG（每张 ≤5 MiB），填写真实工况或“未知”，确认同设备后提交。
5. 在“任务与报告”查看阶段和报错；只有已保存、回读一致的报告才能展示和下载。

[首次测试示例](docs/first-test.md)给出 PDF 获取边界、公开图片来源、可照填的工况、条款复核与检索问题示例，以及每一步的成功判据。不要用历史条款 UID、快照 ID 或未交付的 `data/` 文件填充自己的实例。

## 5. 排错、停止与恢复

| 现象 | 下一步 |
|---|---|
| 页面打不开 / 8001、8002 被占用 | 查看终端及启动诊断；核对进程身份，不重复启动或停止未知程序 |
| 401 / 403 / 429 | 分别核对对应密钥、授权/模型权限、限流与额度；Knowledge 与 Workflow 密钥不能互换 |
| 隧道连接失败或 HTTPS 地址过期 | 在页面恢复隧道；应用新地址后同步 Dify `EVIDENCE_API_BASE_URL` 并发布，再检查 |
| 解析、复核或发布失败 | 打开该任务的“诊断与日志”；补齐来源/依赖/检索标注，不绕过人工复核门禁 |
| 工作流中断 | 有运行 ID 时恢复原运行；没有 ID 且结果不明时先在 Dify 对账，不盲目重复提交 |

结束使用时在项目根目录执行：

```powershell
pwsh -File deploy/stop-portal.ps1 -WhatIf
pwsh -File deploy/stop-portal.ps1
```

停止脚本只处理本实例登记的进程；运行任务未结束时会拒绝停止。关闭浏览器不会停止后台任务。完整停止会结束托管隧道，下次启动需重建并同步临时地址；详细恢复方式见[运行手册](docs/portal-runbook.md#停止与恢复)。

这是单机、单 worker、可信本地用户的 Windows 开发者预览版。没有多用户账号和公网团队隔离；Quick Tunnel 是临时入口。检索通过不证明模型观察或安全结论正确，阶段 E 业务准确性评测尚未开展。

**尚未指定开源许可证，也未建立公开发布仓库。** 当前源码供经项目所有者授权的开发者测试和接续开发；公开再分发前需由所有者确定许可证及资料授权。分享使用 `deploy/export-source.ps1` 从干净 Git HEAD 导出的源码包；接收方仍需自己的 Dify、模型凭据和合法资料。
